# Product overview

## Purpose

ZenTen Vault helps people manage SSH credentials without tying recovery to a single vendor key. A person begins with a passphrase-protected Ed25519 OpenSSH private key for their Vault Key. The app uses it to set up a vault, create associated keys, and automatically recover associated keys found after the vault is set up on another device.

## Who it is for

The intended user already understands the value of SSH keys and needs separate credentials for different services, projects, or environments. They are willing to retain their Vault Key private key and passphrase as important recovery material.

## What the app helps a user do

- Set up a vault using an existing Vault Key.
- Create associated Ed25519 SSH keys.
- View an associated key's public information and, after an explicit confirmation, its private key.
- Check whether backup copies are known to be available.
- Retry a backup check when a connection or remote destination has a problem.
- Set up the vault on another device with the same Vault Key private key and passphrase; valid discovered associated keys are restored automatically.

## Main product promise

A user who still has their Vault Key private key **and** its passphrase can set up the same vault identity on a replacement device. The app then looks for and automatically restores valid discovered associated keys.

## Key concepts

| Concept | Plain-language meaning |
| --- | --- |
| Vault Key | The existing SSH key the user brings to setup. Its private key and passphrase are the root of recovery; the app does not generate a replacement. |
| Vault | The user's local view of generated associated keys and backup status. |
| Associated key | A new SSH key generated by the app for a separate use. It is identified by its creation ID. Technical material may call this a *associated key*. |
| Backup destination | A configured remote service where the app attempts to store a protected backup copy. |
| Backup status | The latest information the app has about a backup's presence or condition. |
| Automatic recovery | The app brings every valid discovered associated key into the local vault during recovery; it does not ask the user to choose keys individually. |

## Product boundaries

ZenTen Vault is not an SSH terminal, SSH agent, Git client, general password manager, or key-registration service. It does not reset or recover a forgotten Vault Key passphrase, and it cannot recreate a Vault Key for which the user holds neither the private key nor the 24 Secret Combinations. It *can* restore a lost Vault Key private key from backup when the user still has the Secret Combinations and passphrase; see [what users must retain](backup-and-recovery.md#what-users-must-retain). The current app does not provide key deletion or vault-reset actions.

## Current maturity

This repository contains a pre-release production build of the app. Stakeholders should use the [scope and roadmap](scope-and-roadmap.md) to distinguish current implementation from intended product behavior. It is not yet released and must not be represented as a production-ready credential vault until the [release gates](scope-and-roadmap.md#release-gates-before-production-use) are complete.
